## First verified analysis: interface surface stiffness
Take a *toy model* of orientation-dependent surface energy

    gamma(theta) = 1 + epsilon cos(n theta).

The orientation-dependent surface stiffness is

    gamma(theta) + d^2 gamma/d theta^2 = 1 - epsilon (n^2 - 1) cos(n theta).

For nonnegative epsilon, its minimum is 1 - epsilon (n^2 - 1). Positive stiffness in every orientation therefore requires epsilon < 1/(n^2-1). The Wolfram evaluator confirmed:

| n-fold symmetry | Critical epsilon (exact) | Decimal |
| --- | --- | --- |
| 4 | 1/15 | 0.0666667 |
| 6 | 1/35 | 0.0285714 |
| 8 | 1/63 | 0.0158730 |

For example epsilon=0.05 gives minimum stiffness of +0.25 (4-fold), -0.75 (6-fold), -2.15 (8-fold). Crossing this threshold creates directions of negative stiffness in this simple energy model and suggests faceting/missing orientations; using it directly in a naive smooth-interface numerical scheme can cause modeling difficulties. Specialized cusp regularization / faceted growth rules may be needed, and any implemented solver must be validated independently.

**Critical caveat:** A.2 currently uses tip steering and persistent branches. Its `anisotropy` setting does NOT equal epsilon in this formula. Do not apply these thresholds to the existing control or market A.2 as an experimentally validated phase-field solver.

## API integration boundaries
The **Wolfram connector inside ChatGPT** can evaluate calculations now; it does not automatically grant API access to a standalone webpage.

For the first phase, use Wolfram in the research/build workflow, commit generated parameter data, and let the browser run entirely offline with no key. An eventual live app API requires a separately configured Wolfram developer credential and quota evaluation, with the secret in server-side environment settings only. **Never put a Wolfram API key into public GitHub, a client-side JavaScript bundle, or a query string generated by public frontend code.** A small serverless proxy may be necessary, and should be postponed until a concrete user-facing feature needs live queries.
